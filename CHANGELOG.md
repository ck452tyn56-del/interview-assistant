# История разработки ассистента

Подробный журнал изменений: что сделано, зачем и как откатиться.
Коммит = этап. Откат на этап: `git checkout <хэш> -- fast_assistant.py`
(взять код этапа) или `git revert <хэш>` (отменить один этап).

## v27.6 — установочные пакеты Windows 10/11
**Коммиты `d59f2c0`+ (15.10, ~20:00)**

**Сборка:** PyInstaller onefile/windowed — один `FastAssistant.exe` (~43МБ)
со всеми зависимостями; `build-windows.bat` — пересборка одной командой.

**Установка:**
- `windows-installer/` — скрипты установщика (install.ps1: Programs + ключ
  в APPDATA + ярлыки + uninstall.bat);
- `FastAssistant-Setup.exe` — односайловый самораспаковывающийся установщик
  (IExpress, рецепт в setup.sed): двойной клик на любом Win10/11 ПК — и всё
  установлено, включая твой API-ключ;
- на не подписанных EXE SmartScreen покажет предупреждение — «Подробнее» →
  «Выполнить в любом случае».

**Переносимость кода:** изменяемые файлы в APP_DIR (%APPDATA% в заморозке,
рядом со скриптом при запуске из исходников); stdout/stderr → UTF-8 (cp1251
ронял EXE); платформенные guard'ы (мьютекс/taskkill — Windows; os.kill —
Linux); pyaudio необязателен; системный звук на Linux через монитор
PulseAudio (сборка под Linux отложена по решению пользователя).

## v27.5 — фикс «услышала, но не ответила» + человекоподобные уточнения
**Коммит `1140ac7` (15.10, ~18:10)**

**Проблема.** Реплика слышна (текст в «Слышу» есть), но ответ не приходит.

**Причина (подтверждена отдельным тестом без GUI).** Сервер Google Live сам
закрывает websocket-соединение сразу после каждого ответа. Приложение
переподключается (~0.5–1с). Если зажать пробел в это окно — сигнал
`activity_start` отправлялся в никуда: сервер получал звук и `activity_end`
БЕЗ начала реплики и игнорировал её. Транскрипция при этом приходила —
отсюда «слышу вопрос, но ответа нет».

**Что изменено:**
- при готовности новой сессии, если пробел ещё зажат — `activity_start`
  досылается автоматически;
- если реплика целиком прозвучала во время переподключения — она доставляется
  целиком (start + накопленный звук + end);
- backlog очереди аудио сливается при реконнекте, но последняя секунда
  сохраняется (там начало речи) — тишина не выстреливается мусором;
- system prompt: реплика может быть уточнением/правкой/подсказкой к прошлому
  диалогу («а если кэша нет?», «нет, я про другой сервер») — модель отвечает
  обновлённым ответом как человек, правки принимает молча;
- активная панель ответа помечается «→ ОТВЕТ [n]» (ответы чередуются между
  панелями — стрелка показывает, куда идёт стриминг).

**Замер скорости (из лога):** реакция 1.4–1.9с от отпускания пробела до
первого слова ответа.

## v27.4 — Reset без разрыва соединения + фикс тихих падений
**Коммит `cf8e44c` (15.10, ~17:55)**

**Проблема.** Кнопка Reset закрывала всё приложение; контекст между
репликами не сохранялся.

**Причина.** Reset делал полный разбор аудио: закрывал потоки PyAudio, пока
фоновые потоки-читатели были внутри `read()` — гонка на уровне C-библиотеки
роняла процесс без единой строчки в логе (те самые «тихие» завершения).

**Что изменено:**
- Reset больше ничего не рвёт: в ту же сессию отправляется текстовый маркер
  «начни новый чистый диалог» (`turn_complete=False` — модель не отвечает на
  сам маркер), панели очищаются. Соединение и аудио живут, скорость не теряется;
- контекст реплик копится в сессии сам (уточнения работают), сбрасывается
  только кнопкой Reset;
- `AudioCapture.stop()` теперь сначала дожидается потоков-читателей
  (`join(timeout=1.5)`) и только потом закрывает потоки — гонка устранена;
- connect после disconnect: старому циклу даётся секунда на выход.

## v27.2 — строгий PTT, глотание пробела, read-only поля
**Коммит `c7eacb3` (15.10, ~17:40)**

**Проблемы.** Пробел печатался в редакторах; в VAD-режиме сервер резал
длинные вопросы по паузам 500мс («половина текста пропала»); в текстовых
полях мигала каретка редактора.

**Что изменено:**
- PTT_STYLE="manual" (строгий режим, теперь по умолчанию): реплика = ровно от
  нажатия до отпускания пробела, сервер ничего не решает и не режет;
  VAD-режим остался опцией в конфиге (`PTT_STYLE = "vad"`);
- кольцевой буфер 1с: звук постоянно пишется в буфер, при нажатии пробела
  последняя секунда приклеивается к реплике — поздно нажал в конференции,
  всё равно поймается начало вопроса;
- пробел глотается системно: в pynput `return False` из фильтра только
  пропускает колбэк — блокирует именно `listener.suppress_event()`;
- все текстовые поля read-only (`state=DISABLED`): каретки нет, правки нет,
  выделение мышью и копирование работают.

## v27.0 — полная переработка v26: только Google Live
**Коммит `a9ceb10` (15.10, ~17:06)**

**Что вырезано из v26:** вторая модель («Gemma»-панель, gemini-2.5-flash) —
лишний раунд к API на 1–3с; захват системного звука с микшированием (loopback);
Interview Mode; Health Monitor.

**Что добавлено/изменено:**
- push-to-talk: пробел держать = говорить; `activityEnd` при отпускании —
  ответ стартует мгновенно, без ожидания паузы VAD 500–800мс;
- авто-fallback моделей: `gemini-3.8-live` → `gemini-3.1-flash-live-preview`
  (thinking=minimal) → `gemini-2.5-flash-native-audio-preview-12-2025` (из v26);
- SOCKS-прокси (`socks5://127.0.0.1:8081`, SSH-туннель plink) для REST и
  websocket — из региона прямой доступ к Gemini API закрыт; websockets не
  наследует прокси из env, поэтому соединение Live патчится явно;
- компактный system prompt (ответы 2–3 предложения);
- чередование двух панелей ответа, автоподгонка шрифта;
- session resumption по-новому: SDK убрал параметр `session_id=` — теперь
  `SessionResumptionConfig(handle=...)`, handle приходит сообщением
  `session_resumption_update`;
- индикатор ⚡ — реальное время от отпускания пробела до первого слова ответа;
- источник звука: микрофон / системный звук (WASAPI loopback, открывается
  лениво при переключении), галка «Пробел в любом окне» для конференций;
- fallback микрофона сохранён: pyaudiowpatch → pyaudio → sounddevice (WDM-KS).
